# Pull request 25: establish an authoritative SonarQube gate

## Summary

- Add the public `stephenlclarke_container-builder-shim` SonarQube project, exact-SHA previous-version scans, imported Go coverage, and a fail-closed clean-analysis check.
- Restrict diagnostic HTTP and gRPC listeners to loopback with a focused security regression.
- Move GitHub token permissions to their consuming jobs and document the current-image workflow's existing exact-main authority proof.
- Exclude generated protobufs and vendored dependencies from maintained-source metrics.
- Add the complete CI and SonarQube badge set and local scan target.

See the companion [issue handoff](ISSUE-24.md) and [issue 24](https://github.com/stephenlclarke/container-builder-shim/issues/24).

## Review map

- `.github/workflows/sonar.yml` generates coverage, verifies the previous-version policy, scans the exact source SHA, waits for the quality gate, and rejects any unresolved issue or hotspot in the analyzed pull request or branch.
- `sonar-project.properties` limits metrics to maintained source while retaining all first-party Go packages.
- `main.go` keeps optional diagnostics inside the builder container's loopback boundary; `main_test.go` makes that invariant executable.
- `.github/workflows/build.yml` and `.github/workflows/current-image.yml` use job-scoped permissions.
- `pkg/fileutils/tarxfer.go` explains why preserving a symlink is safe: the extraction path is confined and later entries cannot traverse symlink parents.
- `Makefile` exposes the same exact-version local SonarQube entry point used by CI.

The ordinary macOS `make lint` and race-test invocations are currently blocked by the host's unaccepted Xcode 27 licence because Go's C toolchain invokes the Apple developer-tool shim. The same pinned linter and complete race/leak suite pass with `CGO_ENABLED=0`; the ordinary invocations remain required final checks after the host licence is accepted. The race suite exposed and now covers a prefetch shutdown race: `Close()` prevents new work before waiting for admitted reads.

## Compatibility and risk

Builder protocol and build behavior are unchanged. The only runtime change narrows debug-only listeners from all interfaces to loopback, reducing their exposure inside the builder container. Release publication retains the same successful-main, exact-current-main, immutable-SHA checks before checkout and publication.

## Upstream handoff

The SonarQube project, badges, and GitHub workflow are Stephen-fork release controls and are not proposed to Apple. The loopback diagnostic hardening is suitable for a later Apple-shaped handoff after the Container-family programme reaches its authorized upstream-publication boundary. No Apple remote is modified by this pull request.
